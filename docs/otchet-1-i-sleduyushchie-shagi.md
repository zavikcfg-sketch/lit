**Вывод: «Reality без интернета» — это НЕ про отсутствие интернета у сервера.** Нода жива, Xray слушает 8443,
фаервол открыт. Значит обрыв в одном из трёх мест:

1. **Ссылка/подписка клиента** — например в Host'е панели указан домен CDN и порт 443 → клиент стучится в Caddy/Cloudflare,
   где никакого Reality нет (на 443 тут Caddy, а Reality на 8443).
2. **Правила маршрутизации в профиле ноды** — трафик с Reality-инбаунда уходит в outbound-«мост» на второй сервер,
   а мост настроен неверно (не тот UUID / порт / ключи / закрыт фаервол) → «connected, но интернета нет»,
   при этом SS-инбаунд ходит напрямую и работает.
3. **Разные ключи/SNI** между профилем и Host'ом, который попадает в подписку.

## 2. Следующие команды (запустить на этом же сервере, от root)

### 2.1. Достать ЖИВОЙ конфиг ноды (главное!)

```bash
docker exec -e NO_COLOR=1 remnanode cli --dump-config > /root/node-config.json 2>&1
sed -i 's/\x1b\[[0-9;]*[a-zA-Z]//g; s/\r//g' /root/node-config.json
wc -l /root/node-config.json
head -60 /root/node-config.json
```

Пришлите `/root/node-config.json` (ключи можно затереть, это личное).

### 2.2. Проверка моста до второго сервера

```bash
# подставьте IP и порт второго сервера
ping -c2 <IP_ВТОРОГО>
timeout 5 bash -c 'cat < /dev/null > /dev/tcp/<IP_ВТОРОГО>/<ПОРТ>' && echo TCP_OPEN || echo TCP_CLOSED
```

### 2.3. Что реально слушает наружу

```bash
ss -tlnp | grep -E 'rw-core|caddy|rw-node'
```

## 3. Что нужно из панели Remnawave (скриншоты или JSON)

1. **Config Profiles** → профиль, привязанный к этой ноде → **JSON целиком**
   (это важнее живого дампа, если что-то одно — давайте профиль).

   и какие инбаунды в него включены.
3. **Ссылка, которую получает клиент** (vless://...), с заменёнными UUID/ключом на XXX.
4. Есть ли в панели **вторая нода** (второй сервер)? Если да — её адрес и какой профиль к ней привязан.

## 4. Быстрый тест «где рвётся» (30 секунд)

На телефоне/ПК с клиентом:

- Подключиться по **Reality-ссылке** и открыть `https://ipinfo.io` — что покажет клиент?
  - *timeout / handshake failed* → неверный порт/SNI/ключи в ссылке (см. гипотезу 1).
  - *connected, но страница не грузится* → скорее всего маршрутизация уводит в мёртвый мост (гипотеза 2).
- Для сравнения подключиться по **Shadowsocks-ссылке** (порт 1234) — работает ли интернет?

## 5. Памятка (не забыть)

- **Reality за Cloudflare-прокси (оранжевое облако) не работает** — CDN терминирует TLS и не проксирует голый TCP.
  Через CDN ходят только VLESS + WS/gRPC/XHTTP с обычным TLS. Reality — только напрямую по IP или серому DNS.
- **443 на этом сервере занят Caddy** (если нужен Reality строго на 443 — придётся освобождать порт
  или проксировать через Caddy/nginx stream, но это отдельная история).
- Нода без выхода в интернет не может быть выходом — ей нужен «мост» на сервер с интернетом
  (Server-Side Routing, см. `diagnostika-remnawave-reality-cdn.md`, §4).
