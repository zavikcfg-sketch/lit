## 1. Что показали тесты

| Тест | Результат | Что это значит |
|---|---|---|
| `Test-NetConnection` с ПК клиента → 8443 | **True** | Из сети клиента порт Reality доступен |
| `Test-NetConnection` с ПК клиента → 1234 | **True** | SS-порт тоже доступен |
| Внешняя проверка TCP 8443 (6 стран) | **Connected везде** | Сервер/фаервол пускают снаружи |

| `realtest.sh`: свой xray-клиент → `127.0.0.1:8443`, ключи из дампа | **EOF, 5 попыток, все неудачны** | Reality-слой ноды не пускает даже корректного локального клиента |
| `xray x25519 -i <privateKey>` | pbk = `gPffJOlscdEQtDKcW38MwW85HNxkV1AdElq5Ph_ZZxA` | Публичный ключ выведен верно, совпадает с тем, что я собрал в ссылке |

**Главный вывод:** проблема не на стороне клиента, не в провайдере и не в портах. Reality-инбаунд
ноды отвергает соединение **сам по себе** — даже когда к нему подключается корректный клиент с правильными
ключом, SNI и shortId. Значит причина внутри: параметры инбаунда/живого конфига либо отсутствие
пользователя в инбаунде.

Дополнительная улика: сервер закрывает соединение за ~50 мс (клиент видит `EOF`), при этом
«неавторизованный» TLS-запрос через тот же порт корректно релеится на настоящий microsoft
(`reality-relay: 200`). То есть TCP и relay-часть работают, отваливается именно авторизация/проверка пользователя.

## 2. Следующий шаг: изолированная матрица (скрипт `realtest2.sh`)

Скрипт поднимает в контейнере **свои** временные xray-сервер и клиент на отдельных портах
(нода не затрагивается) и прогоняет 4 комбинации + отдельный тест против инбаунда ноды:

| Тест | Сервер | Клиент |
|---|---|---|
| 4a | flow в `settings` (как у ноды) | с flow |
| 4b | flow в `settings` (как у ноды) | без flow |
| 4c | flow у пользователя | с flow |
| 4d | без flow | без flow |
| 5 | инбаунд ноды 8443 | ключи из дампа, с flow |

Плюс собирает `/root/nft-dump.txt` (правила фаервола/дропы) и `/root/node-log-last.txt` (сырые логи ноды).

**Как читать:**

- 4a/4c/4d = ipinfo вернул IP сервера, а 5 упал → Reality на машине исправен, виноват живой конфиг
  ноды (ключи/юзеры/flow) → правим профиль/Host/сквад.
- 4a упал, 4c/4d прошли → виновата именно схема «flow в settings» → переносим flow к пользователям.
- упали все четыре → дело в окружении (nft-дропы, сборка) → смотрим nft-дамп.

## 3. Чек-лист по панели (проверить параллельно)

1. **Hosts** → Reality-Host: Address = `13.143.164.175` (или DNS-only домен), Port = **8443**,
   SNI = `www.microsoft.com`, Flow = `xtls-rprx-vision`.
2. **Internal Squads** → включены ли **оба** инбаунда (VLESS-Reality-8443 и Shadowsocks).
3. **Users** → пользователь активен, лимит не исчерпан, HWID не заблокирован.
4. Если Address — домен: `dig +short домен` должен вернуть `13.143.164.175`, а не `104.x/172.67.x`
   (иначе это Cloudflare-прокси, и Reality через него не пройдёт никогда).

Подробный разбор Host'а — в `host-nastroyka-podrobno.md`.
