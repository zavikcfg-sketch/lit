# Host в Remnawave: что это и как настроить под Reality (подробно)

Разбор именно того места, которое чаще всего ломает связку «Reality + панель». Здесь же —
чек-лист значений для вашего сервера и объяснение, почему CDN несовместим с Reality.

---

## 1. Как Host превращается в ссылку

Цепочка такая:

```
Config Profile (inbounds)  →  Node (включает инбаунды)  →  Host  →  Подписка (ссылка vless://)  →  Клиент
                                       ↑
                          Internal Squad (какие инбаунды доступны юзеру)
```

- **Config Profile** — шаблон Xray-конфига ноды: там лежат сами инбаунды (в вашем случае
  `VLESS-Reality-8443` на 8443 и `Shadowsocks` на 1234), ключи Reality, shortIds, SNI.
- **Host** — «точка входа», которую видит клиент. Один Host = один инбаунд.
  Именно из Host'а панель собирает строку подключения для подписки.
- **Подписка** — файл/страница, которую отдаёт панель клиенту. Там список ссылок `vless://...`,
  собранных из Host'ов.

Важно: **Host не может «исправить» параметры инбаунда**, он может их либо унаследовать, либо
переопределить (Advanced Options). Если переопределить неверно — сломается всё.

---

## 2. Где это в панели

`Hosts` → строка нужного Host'а → открыть карточку (Edit).

Поля:

| Поле | Что значит | Для вашего Reality |
|---|---|---|
| **Host visibility** | Показывать ли Host в подписке | Enabled |
| **Remark** | Название, которое увидит клиент | например `FI-Reality-8443` |
| **Select Inbound** | Какой инбаунд профиля обслуживает этот Host | `VLESS-Reality-8443` |
| **Port** | Подставляется автоматически из инбаунда | **8443** (не 443!) |
| **Address** | Куда клиент фактически идёт | **13.143.164.175** или домен в режиме DNS-only |

### Advanced Options (переопределения)

| Поле | Если пусто | Что должно быть у вас |
|---|---|---|
| **SNI** | берётся из `serverNames` инбаунда | `www.microsoft.com` (или пусто — унаследует) |
| **Host** (HTTP-заголовок) | не используется | пусто (это для WS/gRPC, не для Reality) |
| **Path** | не используется | пусто (для Reality не нужен) |
| **ALPN** | не задан | пусто (Reality сама согласует h2/http1.1) |
| **Fingerprint** | chrome по умолчанию | `chrome` |
| **Flow** | панель для Reality/TLS ставит `xtls-rprx-vision` | `xtls-rprx-vision` (**обязательно не пусто** — см. §5) |
| **SpiderX** | `/` | оставить по умолчанию |
| **Allow Insecure** | — | **выключено** (для Reality не нужно) |

Ваш готовый Host должен давать ссылку такого вида:

```
vless://<UUID>@13.143.164.175:8443?type=tcp&security=reality&encryption=none&pbk=gPffJOlscdEQtDKcW38MwW85HNxkV1AdElq5Ph_ZZxA&fp=chrome&sni=www.microsoft.com&sid=4bce9acaa879ed1e&flow=xtls-rprx-vision#FI-Reality
```

**Сверьте по пунктам:**
- адрес и порт — `13.143.164.175:8443` (не домен CDN, не 443);
- `security=reality` (а не `tls`);
- `pbk` — публичный ключ из профиля (для ваших ключей: `gPffJOlscdEQtDKcW38MwW85HNxkV1AdElq5Ph_ZZxA`);
- `sid` — shortId из профиля (`4bce9acaa879ed1e`);
- `sni=www.microsoft.com`;
- `flow=xtls-rprx-vision` — присутствует.

## 3. CDN (Cloudflare) и Reality — почему не работает

**Reality нельзя проксировать через Cloudflare-прокси (оранжевое облако).**
Причина: CDN терминирует TLS у себя и передаёт на origin уже HTTP(S). А Reality — это
собственный TLS-подобный handshake на голом TCP, CDN его просто не пропускает.

Что происходит, если Host указывает на CDN-домен:

```
клиент → Cloudflare:443 (TLS терминируется) → ваш сервер:443 → Caddy (а не Xray!)
```

Клиент вообще не доходит до Reality-инбаунда. На вашем сервере порт 443 занят Caddy
(плюс 80 и админка 2019), а Reality живёт на 8443 — то есть при порте 443 в ссылке
клиент попадает в Caddy, и «интернета нет».

### Как проверить домен

- В панели Hosts: если в **Address** стоит домен — откройте Cloudflare → DNS:
  - **DNS-only (серая тучка)** → годится для Reality;
  - **Proxied (оранжевая тучка)** → Reality не пройдёт. Переключите на серую тучку
    (или просто используйте IP в Address).
- Быстрая проверка с любой машины:
  ```bash
  dig +short ваш-домен
  # если ответ = 104.x / 172.67.x / 188.114.x — это Cloudflare-прокси, Reality не работает
  # если ответ = 13.143.164.175 — всё хорошо
  ```

### А если очень хочется CDN

Тогда Reality не подходит. Нужна схема «CDN-friendly»:
`VLESS + WebSocket (или gRPC/XHTTP) + обычный TLS` на 443, где TLS терминирует Cloudflare,
а на сервере Caddy/nginx проксирует WS на локальный Xray-инбаунд. Это отдельная
переделка профиля — скажите, если захотите, распишу.

## 4. Проверка, что пользователь реально имеет доступ

Помимо Host'а, доступ к инбаунду даётся через **Internal Squads**:

1. `Internal Squads` → ваш сквад → убедиться, что **включены оба инбаунда**:
   `VLESS-Reality-8443` **и** `Shadowsocks`. Если Reality-инбаунд в скваде выключен —
   пользователь получит ссылку, но панель не отдаст его в Xray на этот инбаунд
   (симптом: handshake проходит, а дальше соединение рвётся — ровно как у вас).
2. `Users` → ваш пользователь → проверить: активен, не истёк, лимит трафика не исчерпан,
   нет HWID-блокировки, привязан к нужному скваду.
3. `Nodes` → нода → проверить, что инбаунды включены на самой ноде (Enabled inbounds).
4. Обновить подписку в клиенте (в приложении — «обновить/refresh», не забыть).

## 5. Почему `flow` критичен

В вашем профиле `flow: xtls-rprx-vision` стоит на уровне `settings` инбаунда. По исходникам Xray
этот flow применяется ко всем пользователям (`infra/conf/vless.go`: `account.Flow = c.Flow`),
а в `proxy/vless/inbound/inbound.go` сервер:

- клиента **с** `flow=xtls-rprx-vision` — пускает;
- клиента **без** flow — отклоняет с `client flow is empty`.

Практический вывод: **в ссылке клиента flow обязателен**. Если Host отдаёт ссылку без flow
(например, поле Flow в Host'е пустое) — Reality не заработает.

Есть нюанс: в панели Remnawave для Reality/TLS-инбаундов flow ставится по умолчанию, и чтобы его
выключить, надо явно задать `"flow": ""` в профиле. Обратная ситуация (он выключен, а клиенту нужен)
лечится установкой `"flow": "xtls-rprx-vision"` в профиле/инбаунде или явным значением в Host'е.

## 6. Частые ошибки — таблица

| Симптом | Причина |
|---|---|
| «Подключается», но интернета нет | Портал в ссылке ≠ 8443 (обычно 443 → Caddy) |
| Handshake failed / timeout | Host Address = CDN-домен (оранжевая тучка) |
| Reality в клиенте «красный» | pbk/sid/SNI в ссылке не совпадают с профилем |
| Есть connection, нет интернета | Reality-инбаунд выключен в Internal Squad, либо flow пустой |
| SS работает, Reality нет | Весь блок выше, потому что SS идёт на 1234/IP напрямую |

---

## 7. Что мне прислать (чтобы проверить точно)

1. Скрин или значения из карточки Host'а: **Address / Port / SNI / Flow**.
2. Ссылку `vless://...` из подписки (UUID можно заменить на XXX).
3. Результат `dig +short <домен-из-Address>` (если в Address домен).
4. Скрин Internal Squads → список инбаундов и их переключатели.
